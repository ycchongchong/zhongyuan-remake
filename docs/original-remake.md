## 已知运行稳定性问题

此前无界面测试偶发超时，GDB捕获到 `SIGILL` 和 `SIGSEGV`，部分现场位于内存分配或动态符号调用。现已隐藏核心内部符号、在载入时解析 Linux 动态符号，并加入带超时和完整结束标记的验证工具。根因仍未确定，不能据重复通过就标记修复；详细边界见 `docs/runtime-stability.md` 和 `docs/full-remake-validation.json`。

## 自然征战中发现的跨回合角色停点

正常开局自动征战的第八场战斗，在206年10月、第17399步停在守军角色调整。此前的最后一条电脑命令是机动力不足的攻击；原版仍把方向1写入06A8，随后的人类移动、两次交锋、投降/败北结算及结束回合保留该字节。核心原先在回合交接清成未知，不能判断应移动还是受阻。

新增独立 `computer_role_after_handover` 存档事件，仅对已核对的“电脑攻击不足→人类移动/交锋→一次交接→角色调整”历史恢复方向；跨越归档段也检查每条事件，遇到其他未核对操作仍拒绝恢复。旧角色事件保持原来的含义，不接受存档直接指定暂存方向。界面在原有续行尝试失败后调用此路径。

四种方向的原版受控执行表明，该战局只有方向1会移动，从84到100，机动力35降至32，其余三方向受阻。新C++结果与方向1的全部8192字节SRAM及机动力一致；存档严格重放、伪造方向拒绝、重复调用拒绝及跨存档隔离通过专项检查。原版声音/帧调度仍与C++逻辑边界执行分开，本次不是整局ROM同步证明。

另把第五场战斗自然到达的“2点机动力不足攻击”存档纳入原生和界面回归。该停点已有产品处理，自动征战工具补齐了对现有交接方法的调用；没有将工具遗漏记为新的产品修复。


后续正常征战在同场下一轮又到达角色调整，证明需要保留其他已知电脑移动方向。新增仅由重放计算的交接前暂存值，供同一个新恢复事件使用；旧事件仍清空旧字段以保持兼容。第二个自然存档恢复方向2，原版受控结果为99→98、机动力15→12，四方向结果分别留档；两种来源都检查跨历史分段重放及跨存档隔离。原版逐帧监视确认普通交锋至投降返回、败北返回及结束回合不写06A8；两次停在初始军令8000帧的研究尝试单列为未完成观察，不计为交锋完成证据。
