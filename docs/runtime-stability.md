# 运行稳定性调查

目前不能宣称偶发崩溃已经修复。旧版普通扩展在完整无界面界面测试中，多次被 GDB 捕获到 SIGILL 或 SIGSEGV：有的位于 glibc 分配器，有的通过动态调用跳到无效地址。仅凭这些现场不能确定最初损坏发生在哪里。

本次修改隐藏 C++ 核心及扩展的内部符号，Linux 链接时隐藏静态库符号，并启用立即符号绑定，减少内部实现通过外部符号解析器调用的范围。这是针对已见调用路径的加固，不是已证实的根因修复。诊断构建现在可指定 `ZHONGYUAN_EXTENSION_OUTPUT_DIR`，无需覆盖日常运行的扩展。

## 已完成的验证及边界

- 修改前：普通扩展仅快照读取的三轮压力测试共3000次完成，但完整界面流程仍曾崩溃。
- 修改前：ASan/UBSan 扩展六轮各63项完成。为了运行 ASan，诊断加载器去掉了 Godot 的 RTLD_DEEPBIND，并预载入 ASan 和动态 libstdc++；这种加载方式与普通版本不同，不能替代普通版本验证。
- 修改后：普通扩展完整出征界面测试连续10轮、每轮65项全部完成；完整7组 Godot 回归通过。
- 修改后：独立 C++ 的8组 ASan/UBSan/泄漏检查通过；更新后的诊断扩展65项通过，扩展进程未启用泄漏检查。
- 双方部队界面在软件图形渲染下完成截图检查。上述结果均不代表已经验证全部战斗或长期稳定性。

## 快速诊断输入的音频生命周期修复

上轮 `original_quiz_input` 的退出警告现已定位到一条应用层时序：场景调用 `queue_free()` 后，延迟的音乐/音效请求先于 `tree_exiting` 执行，在同一处理帧内启动并立即停止 WAV 播放。带跟踪的原用例记录了诊断音乐和确认音的资源编号，退出日志中对应两个 WAV 资源及两个播放对象仍被报告为泄漏。该证据不等于已经定位 Godot 内部或历史 C++ 崩溃的根因。

`OriginalSound` 执行延迟播放前现检查拥有场景仍在树内、未排队删除，且未进入关闭流程。清空声音的操作仍可执行，无场景的诊断工具仍可播放；旧场景退出也不会清除新场景的声音。原快速输入测试未经修改连续5次通过且没有退出泄漏警告。新增31项生命周期检查，使用修复前脚本时有12项失败，修复后通过。

验证工具现在把 `objectdb_leaks` 写入每项结果；添加 `--fail-on-leaks` 可将 ObjectDB 警告或详细泄漏行直接判为失败。默认兼容旧行为，功能通过不能解释为没有泄漏；6项 Python 检查覆盖这一差别。音频相关6组178项以严格模式通过，完整回归的最终结果和剩余警告名单见 [音频生命周期记录](audio-lifetime-validation.json)。

复测命令：

```bash
python3 tools/validate_runtime.py --tests original_audio_lifecycle original_quiz_input original_audio original_audio_close opening original_opening_presentation --fail-on-leaks --timeout 240
python3 tests/validate_runtime_test.py
```

本轮未修改 C++、扩展二进制或音画资源，不重复计入原生/消毒器测试。历史 SIGILL/SIGSEGV、未完成的原版音画和整局对照仍单独保留，发布 ZIP 未更新。

完整44组共2069项功能检查通过，用时349.52秒；其中29组仍报告退出泄漏，因此本轮全套结果不是严格无泄漏通过。对 `original_computer_strategy` 单独运行详细日志，原用例和仅在退出前增加 `await OriginalSound.shutdown()` 的诊断副本都通过8项功能检查，但仍报告 WAV/播放对象泄漏。故剩余问题不能仅归因于测试未等待关闭，具体原因仍待定位。两种日志与完整名单已保存在本轮JSON记录。


## 长帧后的音频关闭等待

进一步诊断 `original_computer_strategy`：调用旧shutdown的0.1秒SceneTreeTimer之后仍停在同一处理帧，弱引用显示循环WAV仍被混音器持有。延迟足够的真实时间后对象释放；直接停止PCM再等待也释放，但这不是必须的产品修改。因此保留AudioStreamPlayer.stop的正常停止方式，把shutdown改为基于Time.get_ticks_msec的至少100毫秒等待，使用短异步定时器让出执行。SceneTreeTimer的新定时器会消耗当前长帧的delta，单次0.1秒定时器不能保证给音频线程100毫秒实际清理时间。

32个旧界面回归脚本在直接quit之前补调用现有shutdown，沿用正常窗口关闭的音频清理流程，所有功能断言保留。生命周期回归新增慢帧情况下的真实等待与播放对象弱引用释放检查。此前仅增加旧shutdown仍泄漏的观察保留且得到解释；强制立即退出仍不能作为混音器已清理的证据。专项重复与完整严格回归结果见 `unification-validation.json`。本修复不代表历史SIGILL/SIGSEGV或所有音频还原问题已解决。
