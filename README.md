## 源码仓库范围

仅克隆此仓库可以编译 C++ 核心与扩展；直接启动游戏还需要补齐本地 `assets/` 资源和自己的 ROM。完整回归还需要未上传的 `reference/fixtures/`、`reference/timelines/` 和 `tests/*.json` 样本。下述启动说明针对资源齐备的完整工程。

源码编译示例（不运行依赖样本的测试）：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build build --parallel 4
```

## 启动

Linux x86_64：在本目录执行 `bash start-linux.sh`。源码仓库需要先安装 Godot 4.5 标准版、CMake、C++17 编译器和 Python 3；首次启动会编译核心并导入资源。本地运行包另附 Godot 4.5.2 与 C++ 动态库。

新战局需要读取用户提供的原版文件。原始 ROM 不随源码仓库提供。`reference/manifest.json` 中的默认路径是开发机路径，在其他电脑上请指定自己的文件：

```bash
bash start-linux.sh -- --rom '/你的路径/游戏.nes'
```

项目不附带 `.nes` 文件。严格校验指定版本，避免错误应用其他版本的字段偏移。

Windows 需另行编译 `bin/zhongyuan_core.dll`，再用 Godot 4.5.2 导入项目；目前未提供或验证 Windows 成品包。VS Code 的编译、测试、运行和调试任务保留在 `.vscode/`。

## 当前操作

1. 标题 → 一人游戏 / 二人对战 → 难度 → 性格诊断 → 六君主之一 → 原版状态战局。开场方向键选择，Z / Enter 确认，X 返回。
2. 鼠标点击地图或右侧城池列表查看真实的黄金、土地、商业、人口、统治与驻将。
3. 下方名字图块可选择一个或多个武将。“开发”要求选一名武将，选择土地/商业/人口后确认方案费用；取消不消耗黄金或命令书。
4. “移动武将”后点击相邻己方城池。将领连同各兵种一起移动，出发城必须留将；移动君主会更新所在地。再次点移动可取消。
5. “武将名册”显示全部241条记录，保留原版姓名图块、属性及驻城信息；悬停可查看兵种等属性。“未驻城”不等同于已完整判断其在野、俘虏或其他状态。
6. 地图也支持方向键以原版8像素步幅移动光标，Z确认城池，X取消移动；Tab可切换界面控件。手柄按键映射已加入，尚未实机验证。
7. “存档 / 读档”保存恢复原版状态战局；开场“继续游戏”读取相同文件。“标题”返回开场。

“搜索”要求选择非君主武将并留守至少一将；确认后武将离城，派遣及报告随存档保存。“结束本回合”会推进其余势力和月份；返回月份进入派遣城后打开报告。

“征兵编成”每百人二十金，确认消耗一枚命令书；随后将本城后备兵分配给武将，每将最多一千人。原版补充和撤回兵种顺序由 C++ 计算，编成中途可存档。

双人按六君主的原版顺序轮流行动，第二位不能选择已被第一位选中的君主。难度已影响初始化、命令书及战略 AI。开发文字、方案滚动、动画与精确输入/随机时序仍需校准。

“物资与人事”提供运输、赠送、赏赐黄金/武器/百姓、购买武器、出售宝物、学习、治疗及侦查。商店按各城原版配置开放；运输限相邻己方城池，赠送限相邻其他势力。每条已确认指令消耗一枚命令书，查看本城地形免费。侦查覆盖全部30城，显示原版地形与城堡。

“出征”使用下方已选的武将，选择相邻敌城与主将，确认C++报价后转入战斗记录。出发城必须留将，每百名士兵支付20金，并扣减统治度。**单人和双人战场均可进入布阵。** 点击“开始布阵”，用方向按钮或方向键/WASD移动当前部队，Enter或“确认位置”依次部署；浅色网格为原版部署区域，黄框为当前部队。可在窗口内保存，读档后用“查看战场”恢复。守城时先部署玩家守军，全部确认后电脑自动布置进攻部队。双人对战时，守城方先部署，再按提示交给进攻方；点击“进攻方接手布阵”或按 Enter 开始下一方部署。交接处也可保存恢复。目前双方轮流使用同一键盘/鼠标，实体双手柄与联网未接入。双方布阵完成后，人类进攻方可以点击“进入战术移动”，点击进攻名单切换武将，用方向按钮/WASD移动。费用按原版地形和部队字节字段计算，全军共用机动力，移动立即生效并可保存恢复。进攻方先行动，电脑进攻时可点击“进入电脑先攻”，再逐步推进电脑行动；可使用“阵容 ← / →”在原版四种阵容间调整（免费、即时生效）；选择守城部队后点击“侦察（1机动力）”查看其资料，报告可保存重开且不重复扣点。菜单右侧第二项是“侦察”，此前误记的“恢复”已纠正。现可用“攻击”方向按钮攻击相邻敌军，扣除3点机动力；取消不返还。确认后按原版地形确定交战双方站位，并确定电脑阵容，保存后保持结果。然后点击“进入交战军令”，查看原版16种交战战场和双方兵队，点击本方兵种按钮循环军令；普通武将可选择投降，君主无此选项。双方部队、军令和地图支持保存恢复，旧交战准备存档仍可读取。本方普通武将选择“投降”后，可提交军令，经历可取消的确认和两段对话，最终登记俘虏并恢复战术地图；每个阶段均可保存。普通部队投降后，剩余部队可继续战术行动。进攻主将被俘、普通守军全灭或双方撤退后，可确认对应战果，逐步安置俘虏和军团，再返回战略指令；每一步都能存档。点击“推进交锋”执行一个交锋步骤，或点击“自动推进”；关闭战场窗口、调整军令、保存和进入对话时会暂停。C++已串联兵队军令、朝向、移动、近战、弓箭碰撞、伤亡清理、额外行动及电脑军令，电脑投降可接入现有结算。初始配置后，只能在行动间隙调整军令。此版本按逻辑边界推进，移动/攻击动画等待被折叠，尚非原版逐帧实时交战。武将选择“后退”并抵达交锋边界后，点击撤离行的“继续”，依次处理追击受伤、兵队离散与兵力写回；每一步均可存读档。普通撤离返回战术地图，机动力不重复扣减；这是结束本次交锋，部队仍在战术地图上。普通武将失去战斗能力后，若全军仍可行动则继续；出征主将离场可继续对应战果，电脑守城君主战败后可继续战果及领地接收，玩家君主战败可查看失败报告：全部玩家败北则停留，仍有玩家存活则继续结算领地。交锋中武将体力耗尽后，点击败北行的“继续”登记败北记录，再确认兵力结算；普通武将离场后可继续其余战术行动，出征主将离场后可确认战果，双方俘虏先留在守城，再让剩余进攻军返回各自来源城，城池归属和资源保持不变；玩家君主失败报告支持存读档及返回标题，双人存活方可继续征战，两段确认均可存读档。武将相遇后可点击“进入单挑”，选择牵制、攻击、舍命一击、后退或投降；君主不能投降，电脑出招由C++按原版表决定。每次出招后确认结果，双方轮换；投降可取消，后退保留体力并返回交锋。单挑指令、伤害和结算已经接入，骑马动画、原版单挑画面/对话/音效及逐帧时序仍未还原。电脑左军暂停时，可点击“继续电脑军令”；先检查所有可能暂存值能否得到同样结果，存在歧义时按已追踪的原版正常启动内存恢复，并记录独立存档操作。异常ROM内存写入和完整生命周期穷举仍未验证；玩家施计已接入下述操作；完整电脑战术AI、玩家君主失败演出等仍待还原。

电脑来袭时，守城布阵完成后点击“进入电脑先攻”。电脑按原版选队，评估计策并执行移动或攻击；施计后需确认结果，攻击后点击“进入交战军令”操纵本方守军。机动力耗尽或整圈无动作时转交玩家，守军可移动、侦察、施计、反击和结束回合。各阶段均可保存恢复。电脑作出撤军决定后可执行并确认报告；玩家守军也可主动撤离。原版电脑主将先单独撤回，随后才结算剩余进攻军；出发城满员时，电脑撤退失败仍扣 1 点机动力。战后按原版处理军团、俘虏与城池，确认后轮到下一位君主，避免电脑重复行动。其余未完成的交锋和胜败边界仍保留现场。

玩家行动时，选择本方部队，再在施计栏选择计策和敌军目标，提出方案后可确认或取消。计策按武将智力开放，费用和可用地形取自原版；取消不扣机动力，确认后无论成功与否只扣费一次。结果确认后恢复行动，机动力耗尽时交接；招降导致敌方主将离场时进入战果。方案和结果均支持存读档。此栏使用现代文字控件，原版菜单布局、动画与逐帧随机调度仍未还原。

战术窗口现有“结束本方行动”：主动结束最多保留10点机动力，留给本方下一轮；新预算最多40点。双人出征时双方依次行动，守方可以选择自己的部队移动、调整阵容、侦察进攻部队和发动反击；交锋返回后仍由原行动方继续。守方每次结束才增加战斗回合，完成11个回合后可查看限时报告：由原版规则选出的武将出面，确认后进攻军返回各自来源城，再安置双方俘虏，守方保有城池，资源不变。报告、撤军和俘虏安置均可逐步存读档，最终返回当前战略回合。单人交给电脑时保存停点，可继续已接入的守军评估、移动、攻击和施计；未实现的分支仍会保留现场，不能代替电脑跳过回合。守方可撤往本势力驻将最少的其他城池。限时报告的原版逐字对话、头像及演出时序尚未还原。

电脑守城君主在交锋中败北后，点击“确认君主败北战果”，先完成战场军团、俘虏和占城结算，再逐城核对30城归属，接收其余败方领地。驻将忠诚和城池资源按原版规则调整，已经占领的目标城不会再次扣减。每一步都可存档；全部核对后确认返回战略指令。玩家君主失败报告和电脑先攻已经接入；完整败北演出、全局随机时序及全部战斗分支仍未完成。

## 两套现有场景

- `original_campaign.tscn`：默认开场进入的原版状态战局，使用 `OriginalSession` / `OriginalState` C++ 核心。
- `main.tscn`：保留的旧30城可玩原型，可用 `bash start-linux.sh res://main.tscn` 启动。它仍使用自定经济、自动战斗和简化 AI，不能当作原版还原结果。
- `reference_data.tscn`：原版数据核对工具，运行 `bash start-linux.sh res://reference_data.tscn`。

原版状态战局使用 `campaign-native-original.json`，格式 `native-original-v2`，兼容读取 v1；保存完整8192字节状态、随机游标、帧计数、AI 阶段、待处理战斗、开发/搜索/编成和回合记录。文件保存在游戏目录 `.user-data` 下。旧原型的 `campaign-original-map.json`、`campaign-30.json`、`campaign.json` 均保留，不与新状态格式互读。此格式是电脑重制工程的存档，原版“记录”流程仍未重写。

## 核心文件

- `native/src/original_rom.cpp`：原版只读导入、初始化、图块/坐标/道路/规则表。
- `native/src/original_state.cpp`：真实城池与武将状态、移动、开发、搜索、命令书、日期和月结算。
- `native/src/original_expedition.cpp`：原版出征报价、费用、留守检查、外交限制、主将标记和武将转入战斗记录。
- `native/src/original_commands.cpp`：运输、赠送、赏赐、商店、侦查，失败时保持资源、命令书和随机游标不变。
- `native/src/original_ai.cpp`：原版战略 AI、调将、内政、征兵、非玩家战斗结算与玩家战斗入口。
- `native/src/original_session.cpp`：原生战局会话、开发确认/取消、搜索派遣/返回/招募、时钟与随机游标、事务式存档恢复。
- `native/src/opening.cpp`：13题/26分支性格诊断与开场状态机。
- `native/godot/original_data.cpp`：图块与原生战局的 Godot 接口、存档文件 I/O。
- `scripts/original_campaign.gd`：地图、名册、菜单与输入；不计算开发、移动或搜索或征兵规则。
- `native/src/campaign.cpp`：保留的旧原型核心。
- `reference/fixtures/`：独立原版截图、名称掩码、初始化与命令/结算前后的 SRAM 样本。
